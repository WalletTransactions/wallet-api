# sync-pull Specification

## Purpose
Выдача изменений клиентам синка через `GET /sync/pull`
(`operationId: syncPull`): два независимых потока по курсору `seq`,
страницы, которые не разрезают атомарные группы, и восстановление после
курсора, который сервер никогда не выдавал.

## Requirements

### Requirement: Два потока в одном ответе
Pull SHALL отдавать одним ответом два потока: `ledger` (данные леджера
вызывающего, включая его собственные валюты, пары, курсы и иконки) и
`reference` (только общие строки с `ledger_id IS NULL`). У каждого потока
свой курсор: `ledger_seq` и `reference_seq`.

#### Scenario: Свой курс и общий курс
- **WHEN** в базе есть общий курс пары и свой курс леджера на ту же дату
- **THEN** свой курс приходит в `ledger.changes.currency_pair_rate`, общий — в `reference.changes.currency_pair_rate`

### Requirement: Изменения после курсора
Каждый поток SHALL возвращать строки синхронизируемых таблиц с `seq` больше
курсора по возрастанию `seq`, сгруппированные по таблице в `changes`, и
`next_seq` — наибольший `seq` страницы. Без новых строк `next_seq` равен
курсору. Курсор по умолчанию — `0`.

#### Scenario: Нечего отдавать
- **WHEN** клиент запрашивает поток с курсором, равным голове
- **THEN** `changes` пуст, `next_seq` равен присланному курсору

### Requirement: Страница не разрезает группу seq
Лимит `limit` (по умолчанию `500`) SHALL задавать, сколько строк набирать,
но страница дополняется всеми строками с тем же `seq`, что у последней
набранной. Группа одного push-батча никогда не делится между ответами.

#### Scenario: Батч больше лимита
- **WHEN** один батч дал 700 строк с одним `seq`, клиент просит `limit=500`
- **THEN** в ответе все 700 строк этого `seq`

### Requirement: Полная строка и tombstone
Строка в `changes` SHALL быть полным набором колонок таблицы (`uuid`,
`ledger_id`, `seq`, `deleted_at`, `updated_at`, `updated_by` и бизнес-колонки).
Мягко удалённые строки отдаются как обычные, с заполненным `deleted_at`.

#### Scenario: Удалённый на другом устройстве счёт
- **WHEN** счёт мягко удалён после курсора клиента
- **THEN** строка счёта приходит с непустым `deleted_at`

### Requirement: Точные значения в ответе
`operation.amount` и `currency_pair_rate.rate` SHALL отдаваться JSON-строками
с десятичной записью, `icon.content_sha256` — hex-строкой.

#### Scenario: Сумма с копейками
- **WHEN** push записал `amount` = `"0.10"`
- **THEN** pull отдаёт `amount` строкой `"0.10"`, а не числом

### Requirement: Сброс курсора, ушедшего дальше головы
Если курсор потока больше его головы (такого `seq` сервер не выдавал), pull
SHALL отдать поток с нуля, `reset: true` и `reset_reason: "ahead"` в этом
потоке и записать warn `sync_pull_cursor_reset`. Без сброса — `reset: false`
и без поля `reset_reason`. Голова только растёт, так что параллельный push
ложного сброса не даёт.

#### Scenario: Курсор от пересозданной базы
- **WHEN** клиент присылает `ledger_seq=146` при голове потока `13`
- **THEN** `ledger.reset` = `true`, `ledger.reset_reason` = `"ahead"`, поток отдан с начала, `next_seq` ≤ 13

#### Scenario: Обычная страница
- **WHEN** курсор не больше головы и поток не вычищен дальше курсора
- **THEN** `reset` = `false`, поля `reset_reason` в потоке нет

### Requirement: Леджер потока в ответе
Поток `ledger` SHALL нести `ledger_id` леджера, к которому он относится,
чтобы клиент заметил смену леджера (принятое приглашение, другой
пользователь на устройстве) и сам начал поток с `0`.

#### Scenario: Переход в общий леджер
- **WHEN** пользователь принял приглашение, и устройство делает следующий pull
- **THEN** `ledger.ledger_id` — новый леджер

### Requirement: Нечисловые параметры
Нечисловое значение `ledger_seq`, `reference_seq` или `limit` SHALL
заменяться значением по умолчанию (`0`, `0`, `500`), а не давать ошибку.

#### Scenario: Мусор в курсоре
- **WHEN** `ledger_seq=abc`
- **THEN** поток `ledger` отдаётся с курсора `0`

### Requirement: Флаг эквивалента в строке валюты
Строка `currency` в pull SHALL нести булево `show_in_equivalent` в обоих
потоках: у общих валют оно задаётся сервером, у своих — последним push.
Валюты, созданные до появления флага, отдаются с `true`.

#### Scenario: Валюта до миграции
- **WHEN** клиент делает полный pull после миграции, а валюта создана раньше
- **THEN** её строка несёт `show_in_equivalent: true`

#### Scenario: Флаг снят на другом устройстве
- **WHEN** другое устройство того же леджера запушило валюту с `show_in_equivalent: false`
- **THEN** pull после курсора отдаёт эту валюту с `show_in_equivalent: false`
