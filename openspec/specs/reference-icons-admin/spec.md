# reference-icons-admin Specification

## Purpose
Управление администратором общим набором иконок (`ledger_id IS NULL`):
создание из загруженного содержимого, переименование и удаление, с доставкой
каждого изменения на устройства через поток справочников синка.

## Requirements

### Requirement: Только администратор
Ручки `/api/admin/icons*` SHALL требовать аутентификацию и роль `admin` в
claim'е `role` токена; claim `device_id` не нужен. Без токена — `401`, с
другой ролью (`user`, `support`) или без claim'а — `403` `forbidden`.

#### Scenario: Обычный пользователь
- **WHEN** токен с `role` = `user` отправляет `POST /api/admin/icons`
- **THEN** ответ `403`, общий набор не изменён

#### Scenario: Браузерная сессия администратора
- **WHEN** токен без `device_id` с `role` = `admin` и scope `wallet:write` создаёт иконку
- **THEN** запрос обработан, леджер и устройство не провизионируются

### Requirement: Создание общей иконки
`POST /api/admin/icons` (`createReferenceIcon`) с JSON `name` (непустая
строка после обрезки пробелов, до 64 символов), `icon_type` (целое ≥ 0) и
`content_sha256` (64 hex) SHALL создать общую иконку с новым `uuid` и ответить
`201` с `uuid`, `name`, `icon_type`, `content_sha256`. Некорректное поле —
`400`; содержимое с таким хешем не загружено через `POST /sync/blobs` — `400`
«содержимое не загружено»; живая общая иконка с тем же `name` уже есть —
`409`.

#### Scenario: Новая иконка
- **WHEN** администратор загрузил картинку в `/sync/blobs` и создаёт иконку `Cinema` с её хешем
- **THEN** ответ `201`, иконка видна в `GET /api/reports/admin/icons` в разделе общих

#### Scenario: Хеш без содержимого
- **WHEN** `content_sha256` корректен, но такого blob нет
- **THEN** ответ `400`, иконка не создана

#### Scenario: Дубль имени
- **WHEN** живая общая иконка `Cinema` уже есть
- **THEN** ответ `409`

### Requirement: Правка общей иконки
`PATCH /api/admin/icons/{uuid}` (`updateReferenceIcon`) с любым
подмножеством `name`, `icon_type` (те же правила, что при создании) SHALL
менять общую иконку и возвращать её. Содержимое картинки этой ручкой не
меняется. Неизвестный, удалённый или не общий (`ledger_id` заполнен) `uuid`
— `404`; дубль имени — `409`; пустое тело — `400`.

#### Scenario: Переименование
- **WHEN** администратор меняет `name` общей иконки на `Кино`
- **THEN** ответ `200` с новым именем, `uuid` и `content_sha256` прежние

#### Scenario: Своя иконка пользователя
- **WHEN** `uuid` принадлежит иконке какого-то леджера
- **THEN** ответ `404`, строка не изменена

### Requirement: Удаление общей иконки
`DELETE /api/admin/icons/{uuid}` (`deleteReferenceIcon`) SHALL мягко удалять
общую иконку (`204`), если на неё не ссылается ни одна живая строка
`account` или `currency` любого леджера; иначе — `409` с числом ссылок
`in_use`. Неизвестный, уже удалённый или не общий `uuid` — `404`. Содержимое
в `blob` не удаляется.

#### Scenario: Иконка используется
- **WHEN** у какого-то счёта `icon_uuid` указывает на удаляемую иконку
- **THEN** ответ `409`, `in_use` ≥ 1, иконка жива

#### Scenario: Неиспользуемая иконка
- **WHEN** ссылок на иконку нет
- **THEN** ответ `204`, следующий `GET /sync/pull` отдаёт её tombstone в потоке справочников

### Requirement: Изменения едут в поток справочников
Каждое создание, правка и удаление SHALL быть одной транзакцией с одним
новым `seq` потока справочников, `updated_by` = NULL, и приходить на все
устройства обычным `GET /sync/pull` (раздел `reference`).

#### Scenario: Телефон получает новую иконку
- **WHEN** администратор создал общую иконку, а устройство затем вызывает `GET /sync/pull` со своим `reference_seq`
- **THEN** в `reference.changes.icon` есть строка с её `uuid`, `name`, `icon_type`, `content_sha256`
