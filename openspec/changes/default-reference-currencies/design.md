## Context

Общие иконки уже приходят миграциями (`000037`, `000038`, генератор `gen_default_icons.py`). Справочник валют и пар — следующий слой: у `currency` есть `icon_uuid NOT NULL`, у `currency_pair` — база и квота. Схема допускает общие строки (`ledger_id IS NULL`) и раздаёт их через поток `reference` (`next_seq` на `00000000-0000-0000-0000-000000000001`); для иконок это уже работает.

## Goals / Non-Goals

**Goals:**
- Те же 17 валют и 31 пара, что в стартовом наборе телефона, есть в базе по умолчанию.
- Миграция безопасна на живой базе: ничего не затирает, повторный накат ничего не меняет.

**Non-Goals:**
- Курсы валют (`currency_pair_rate`) — справочник без курсов, как и стартовый набор телефона.
- Автоматическая синхронизация с `seed.json` при изменении набора телефона: следующее изменение — новой миграцией.
- Дедупликация общих и своих валют у существующих леджеров (см. «Риски»).

## Decisions

1. **Снимок набора телефона, не «полный» справочник ISO 4217.** Это единственный состав, согласованный с владельцем (`new-user-default-set`): 17 валют, 31 пара. Больше валют — отдельное решение (и отдельная миграция, как и для иконок).

2. **Детерминированные `uuid`** `md5('reference-currency:' || iso)` и `md5('reference-currency-pair:' || symbol)` — как у иконок (`md5('reference-icon:' || lower(name))`): повтор не плодит дубли, `ON CONFLICT (uuid) DO NOTHING`, откат находит свои строки без хранения списка id.

3. **Иконка по имени, а не по `uuid`.** Валюте нужна живая общая иконка с именем из набора (`Flag Euro`, `Serbian flag`, …): иконка могла быть пересоздана администратором с другим `uuid`, а имя в общем пространстве уникально (`uq_icon_name_reference`). Нет иконки — валюта (и пары с ней) пропускается, миграция не падает.

4. **Пропуск при совпадении кода или названия** (без учёта регистра): обе уникальности (`uq_currency_iso_reference`, `uq_currency_name_reference`) защищают миграцию от ошибки, но пропускать надо раньше, чем сработает индекс — иначе накат упадёт целиком. Пара опирается на **живые общие валюты по коду**, в том числе администраторские: пара `EURUSD` остаётся, даже если `EUR` завёл администратор.

5. **Названия — английские, как в `seed.json`.** Общая валюта на телефоне показывается названием по ISO на языке телефона (`currency-directory`), серверное `name` — запасное и название на вебе. Русские названия — отдельное решение (их можно будет править экраном администратора).

6. **Откат через `foreign_key_violation`.** Валюту, на которую уже ссылается кошелёк или пара леджера, удалить нельзя (внешний ключ `NO ACTION`). Откат перебирает строки набора и пропускает те, что держат ссылки, вместо жёсткого списка таблиц, которые могут появиться позже.

7. **Генератор по образцу иконок:** манифест `migrations/default_currencies/manifest.json` + `collect --android` + `build`; SQL руками не правится, тест сравнивает файл с выводом генератора.

## Risks / Trade-offs

- [У существующих леджеров рядом со своей `USD` появится общая `USD`] → клиент при совпадении кода предпочитает свою строку (`currencies-api`: «клиент при совпадении кода предпочитает свою строку общей»); общая нужна телефонам и леджерам без своей валюты. Проверяется на test после выкатки.
- [Название общей валюты на веб-экране справочника — английское] → осознанно (решение 5); правится администратором.
- [Набор телефона изменится, а миграция устареет] → снимок на момент миграции, как у иконок; расширение — новой миграцией и тестом `test_matches_phone_seed`.

## Migration Plan

Накат `000039` через обычный deploy `wallet-api` (golang-migrate). Откат `000039.down.sql` убирает только строки набора без ссылок. Клиенты ничего не ждут: справочник приходит через `reference`-поток.
