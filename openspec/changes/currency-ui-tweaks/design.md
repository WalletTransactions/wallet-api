# Design

## Context

- `currency` — это `ReferenceOrLedger`-таблица. Общие валюты (`ledger_id IS
  NULL`) пишет только сервер. Свои валюты до сих пор приходили только с
  телефона через push. REST для валют нет.
- Push собирает один `INSERT … ON CONFLICT … DO UPDATE` на строку по
  `TableSpec::columns` и читает каждое значение через `row.at(col)`. Если
  ключа нет, вылетает исключение, и весь батч получает `400 invalid_row`.
  Прецедент `account.kind` сознательно сделан обязательным.
- Параметры `db::exec` — только `std::vector<std::string>`: SQL NULL
  параметром передать нельзя.
- Pull сериализует строку целиком (`to_jsonb(t.*)`), поэтому новая колонка
  попадает в ответ без отдельной правки.
- `/api/currency-pairs*` уже реализует нужный образец: репозиторий с
  проверкой видимости своих и общих строк, один `next_seq(ledger)` на
  изменение, маршруты в `currency_pairs.cpp`, scope в `access.cpp`.
- Символ пары (`currency_pair.symbol`) — это склейка ISO-кодов базы и
  котировки. Телефон ищет пару по символу (`WalletDbCRUD.getCurrencyPairIdBySymbol`).

## Goals / Non-Goals

**Goals:**
- Флаг хранится, синкается в обе стороны и не ломает необновлённые телефоны.
- Веб может делать со своей валютой всё то же, что форма валюты на
  телефоне.

**Non-Goals:**
- Правка общих валют через API. Их меняет только администратор SQL.
  Скрыть общую валюту из эквивалента для одного леджера нельзя (см. Risks).
- `GET /api/currencies` не делается: справочник уже отдаёт wallet-report.
- Фильтр по флагу на сервере не делается: `/api/reports/currencies` отдаёт
  все валюты, фильтрует клиент.

## Decisions

### D1. Колонка в `currency`, а не отдельная таблица предпочтений
`show_in_equivalent boolean NOT NULL DEFAULT true`. Это атрибут валюты, как
`precision`, и едет в синк тем же путём.
Альтернатива — таблица `ledger_currency_pref(ledger_id, currency_uuid,
show_in_equivalent)`. Она позволила бы скрывать и общие валюты по-леджерно,
но потребовала бы новой синк-таблицы, порядка применения и хранения на
клиенте. Для мелкой правки интерфейса это непропорционально.

### D2. Необязательная колонка в `TableSpec`: строка без ключа её не трогает
`TableSpec::optional_columns` — подмножество `columns`. Если колонки из
`optional_columns` нет в JSON строки:
- её нет в списке колонок `INSERT`, и работает `DEFAULT true`;
- её нет в `DO UPDATE SET` и в `update_by_uuid_sql`, и прежнее значение
  остаётся.

Если ключ есть, значение обязано быть JSON-boolean, иначе `invalid_row` с
именем поля.
Альтернатива — `COALESCE($n, currency.show_in_equivalent)`. Её отвергли:
`db::exec` не умеет NULL-параметры, а пустая строка в роли «NULL» стала бы
ловушкой для остальных колонок.

### D3. Почему флаг не обязательный, как `account.kind`
У `kind` нет безопасного значения по умолчанию, а у флага есть: `true`
даёт поведение до правки. Если сделать флаг обязательным, необновлённые
телефоны получали бы `400` на любой push с валютой и переставали бы
синкаться совсем.

### D4. REST валют — копия устройства `/api/currency-pairs*`
`src/currencies_repo.{hpp,cpp}` и `src/currencies.cpp` (`currencies_api::register_routes`),
ветка `/api/currencies` в `access.cpp`. Префикс `/api/currency-pairs` её не
покрывает: строки расходятся после `currenc`. Каждое изменение — одна
транзакция: `next_seq(ledger)`, затем `INSERT`/`UPDATE`, `updated_by =
NULL`. Леджер при `POST` создаётся тем же помощником, что у пар.
Ответ `POST`/`PATCH` — та же форма строки, что элемент
`/api/reports/currencies` (uuid, name, iso_code, symbol, precision,
icon_uuid, icon_sha256, show_in_equivalent, is_own). Тогда веб может
подставить её в свой справочник без перезапроса.
Альтернатива — писать валюту с веба через `/sync/push`. Её отвергли: вебу
пришлось бы вести `batch_id`, повторы и `missing_reference`, а пары уже
задали REST-образец.

### D5. Проверки повторяют форму валюты на телефоне
- Уникальность кода проверяется против **всех** видимых живых валют, своих и
  общих, как `getCurrencyByISO` на телефоне. Индексы `uq_currency_*_ledger`
  сами по себе общую валюту не учитывают, поэтому нужна явная проверка в
  репозитории. Затем `409 duplicate` с `field`. Нарушение индекса в гонке
  тоже отображается в `409`.
- Удаление: `409 currency_in_use`, если есть живой `account_operating` с
  этой валютой или живая пара, где она база или котировка. Это то же
  правило, что `IsCurrencyInUse` на телефоне.
- `precision` 0–8: это `CHECK` таблицы, а не 0–10, как у пар.

### D6. Код валюты, входящей в пару, не меняется
`PATCH` с другим `iso_code` при живой паре с этой валютой даёт `409
currency_in_pair`.
Альтернатива — в той же транзакции пересчитать `symbol` всех своих пар с
этой валютой, с тем же `seq`. Её отвергли: телефон тогда тоже должен
пересчитывать символы при локальной правке, а локальные курсы, найденные по
старому символу, в окне до синка ушли бы не туда. Запрет проще и
симметричен на всех клиентах. Если понадобится, пересчёт можно сделать
отдельным change.

## Правки в других сервисах

- **wallet-report** (`wallet-report: currency-ui-tweaks`): `GET
  /api/reports/currencies` отдаёт `show_in_equivalent`, `is_own`,
  `icon_uuid`, `precision`. GRANT не нужен: `wallet_reader` читает таблицы
  целиком (`schema/role/wallet_reader.sql`).
- **android-wallet** (`android-wallet: currency-ui-tweaks`): локальная
  колонка, push и pull флага, те же правила формы (общая валюта только для
  чтения, код валюты пары не меняется).
- **wallet-web** (`wallet-web: currency-ui-tweaks`): форма валюты поверх
  этого REST.
- **wallet-telegram**: валюты не пишет, правка не нужна.
- **wallet-gateway**: без правок, `/api/*` → wallet-api.

## Risks / Trade-offs

- [Общую валюту нельзя скрыть из эквивалента для одного леджера, а своя с
  тем же кодом запрещена (D5)] → это принято. Если понадобится, следующий
  шаг — альтернатива из D1.
- [Push строки без ключа не может сбросить флаг] → так задумано: «нет
  ключа» значит «клиент о флаге не знает».
- [Правка валюты с веба и с офлайн-телефона одновременно] → действует
  последняя запись по `seq`, как у пар и курсов. Отдельного разрешения
  конфликтов нет.

## Migration Plan

1. `000026_currency_show_in_equivalent.up.sql`: `ALTER TABLE currency ADD
   COLUMN show_in_equivalent boolean NOT NULL DEFAULT true` + `COMMENT`.
   Константный DEFAULT не переписывает таблицу. `seq` не трогается: клиенты
   знают значение по умолчанию сами.
2. Выкатить wallet-api, затем wallet-report, затем клиентов. Старые клиенты
   продолжают работать (D2), новые REST-ручки им не нужны.
3. Откат: `down.sql` делает `DROP COLUMN`. Перед ним откатываются
   wallet-report и клиенты, которые читают поле.
