# Spec Delta

## Purpose

Хранение и синхронизация контрагентов и признака долгового кошелька, на
которых строится учёт долгов во всех клиентах и отчётах.

## ADDED Requirements

### Requirement: Контрагент
Контрагент SHALL храниться строкой `counterparty` леджера с обязательными
полями `name`, `comment`, `is_archived` и необязательной ссылкой
`icon_uuid`. Имя SHALL быть уникально среди живых контрагентов леджера без
учёта регистра и пробелов по краям. Контрагенты общие для всех участников
леджера.

#### Scenario: Новый контрагент
- **WHEN** push несёт `counterparty` с `name` = `Вася`
- **THEN** ответ `200`, а строка появляется в pull у всех участников леджера

#### Scenario: Дубль имени
- **WHEN** push несёт `counterparty` с `name` = `вася`, при живом контрагенте `Вася` другого `uuid`
- **THEN** ответ `409`, `error` = `duplicate_name`, батч не применён

#### Scenario: Строка без обязательного поля
- **WHEN** push несёт `counterparty` без `is_archived`
- **THEN** ответ `400`, `error` = `invalid_row`, `detail` называет поле

### Requirement: Долговой кошелёк — живая строка account_debt
Кошелёк SHALL считаться долговым, пока у него есть строка `account_debt` с
тем же `uuid` и `deleted_at IS NULL`. Строка допустима только для счёта со
строкой `account_operating` и только со ссылкой `counterparty_uuid` на
существующего контрагента того же леджера. `due_date` — необязательная
дата, `comment` — строка. Мягкое удаление `account_debt` возвращает кошелёк
в обычные, не трогая его операции и баланс.

#### Scenario: Пометить кошелёк долговым
- **WHEN** push несёт `account_debt` с `uuid` существующего кошелька и `counterparty_uuid` существующего контрагента
- **THEN** ответ `200`, а в балансовых функциях этот кошелёк отдаётся с этим `counterparty_uuid`

#### Scenario: Долг на категории
- **WHEN** push несёт `account_debt` с `uuid` счёта без строки `account_operating`
- **THEN** ответ `409`, `error` = `missing_reference`, батч не применён

#### Scenario: Несуществующий контрагент
- **WHEN** push несёт `account_debt` с `counterparty_uuid`, которого нет в леджере
- **THEN** ответ `409`, `error` = `missing_reference`

#### Scenario: Снятие признака
- **WHEN** push несёт `account_debt` с `"deleted": true`
- **THEN** кошелёк отдаётся с `counterparty_uuid` = `NULL`, его операции и баланс не меняются

### Requirement: Несколько займов одному контрагенту
Пара «контрагент + валюта» SHALL NOT быть уникальной: у одного контрагента
может быть несколько долговых кошельков в одной валюте, каждый со своими
`due_date` и `comment`.

#### Scenario: Два займа одному человеку в одной валюте
- **WHEN** у контрагента уже есть долговой кошелёк в USD и push несёт второй `account_debt` с тем же контрагентом и кошельком в USD
- **THEN** ответ `200`, оба кошелька существуют

### Requirement: Целостность контрагента и долга
Контрагента с живыми `account_debt` SHALL NOT быть можно удалить. Мягкое
удаление кошелька SHALL каскадно мягко удалять его `account_debt`. Архивация
контрагента (`is_archived`) не удаляет и не меняет его долги.

#### Scenario: Удаление контрагента с долгами
- **WHEN** push несёт `counterparty` с `"deleted": true`, у которого есть живой `account_debt`
- **THEN** ответ `409`, `error` = `counterparty_in_use`, батч не применён

#### Scenario: Удаление контрагента без долгов
- **WHEN** push несёт `counterparty` с `"deleted": true`, и живых `account_debt` у него нет
- **THEN** ответ `200`

#### Scenario: Удаление кошелька с долгом
- **WHEN** кошелёк с живым `account_debt` мягко удалён
- **THEN** его `account_debt` тоже помечен удалённым и отдаётся в pull с `deleted_at`

#### Scenario: Архивный контрагент
- **WHEN** push несёт `counterparty` с `is_archived` = `true`
- **THEN** ответ `200`, `account_debt` контрагента остаются живыми

### Requirement: Долг и актив не исключают друг друга на сервере
Сервер SHALL принимать кошелёк, у которого одновременно есть живые
`account_asset` и `account_debt`; запрет держит клиент.

#### Scenario: Оба признака
- **WHEN** push несёт `account_debt` для кошелька с живым `account_asset`
- **THEN** ответ `200`

### Requirement: Направление долга — по знаку баланса
Сервер SHALL NOT хранить в операции признак «дал / взял / вернул».
Направление долга определяется знаком баланса долгового кошелька: «+» —
контрагент должен леджеру, «−» — леджер должен контрагенту.

#### Scenario: Знак баланса
- **WHEN** на долговой кошелёк переведено 100, затем с него возвращено 150
- **THEN** баланс кошелька в отчётных функциях равен `-50`

### Requirement: Балансовые функции отдают контрагента
`v_account_operating`, `f_balance_to_date`, `f_balance_to_dates` и
`f_balance_series` SHALL отдавать в конце набора колонок `counterparty_uuid`
(`NULL` — кошелёк не долговой). Прежние колонки и их порядок не меняются.

#### Scenario: Долговой и обычный кошельки
- **WHEN** `f_balance_to_date` вызвана для леджера с одним долговым кошельком и одним обычным
- **THEN** у долгового `counterparty_uuid` не `NULL`, у обычного — `NULL`

### Requirement: Операция с долговым кошельком в ленте
`f_operations_for_period` SHALL отдавать `kind = 'debt'` для перевода, у
которого ровно одна сторона — долговой кошелёк. Перевод между двумя
долговыми кошельками и проводка «долговой кошелёк ↔ категория» (прощение,
проценты) SHALL сохранять прежний вид (`transfer`, `expense`, `income`).

#### Scenario: Выдача в долг
- **WHEN** есть перевод «Наличные → Вася · USD»
- **THEN** в ленте за период строка имеет `kind` = `debt`

#### Scenario: Прощение долга
- **WHEN** есть проводка «Вася · USD → категория Списание долгов»
- **THEN** строка имеет `kind` = `expense` и учитывается как расход

### Requirement: Сводка по долгам
`f_debts_for_period(p_ledger_id, p_from, p_to, p_eq_currency)` SHALL
возвращать строку на каждый живой долговой кошелёк (включая нулевой и
архивный): контрагент (`uuid`, `name`, `is_archived`), кошелёк (`uuid`,
`name`, `is_archived`), валюта, `due_date`, `comment`, баланс на начало
периода, поступления и выбытия за период (в валюте кошелька), баланс на
конец, а также эквиваленты суммы в `p_eq_currency` по последнему курсу
`<= p_to` (`NULL` без курса).

#### Scenario: Остаток после частичного возврата
- **WHEN** на «Вася · USD» переведено 1000 и возвращено 400 в одном периоде
- **THEN** строка имеет начальный баланс 0, поступления 1000, выбытия 400, конечный 600

#### Scenario: Нет курса
- **WHEN** для валюты кошелька нет курса к `p_eq_currency`
- **THEN** поля эквивалента `NULL`, остальные поля заполнены
