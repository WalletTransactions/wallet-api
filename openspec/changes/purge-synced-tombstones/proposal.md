# Proposal

## Why

Мягко удалённые строки (`deleted_at IS NOT NULL`) в таблицах синка живут на
сервере вечно, хотя нужны только затем, чтобы каждое устройство узнало об
удалении. Сервер знает все устройства (`device`), но не знает, до какого `seq`
каждое из них дочитало поток: колонка `device.last_ack_seq` есть в схеме, но код
её не пишет. Поэтому сейчас нельзя понять, когда tombstone можно удалить
физически.

## What Changes

- `GET /sync/pull` записывает курсоры из запроса (`ledger_seq`,
  `reference_seq`) как подтверждение устройства: всё до этого `seq` клиент
  применил и сохранил. Новое поле `device.last_ack_reference_seq` для потока
  справочников.
- Новый необязательный параметр `ledger_id` у `GET /sync/pull`: подтверждение
  потока леджера записывается, только если леджер клиента совпадает с леджером
  устройства (курсор от чужого леджера — не подтверждение).
- Горизонт чистки потока — минимальный подтверждённый `seq` среди активных
  устройств, которые читают поток. Устройства без `pull` больше 90 дней и
  устройства, которые никогда не читают (бот: только push), в горизонт не входят.
- Физическое удаление tombstone с `seq <= горизонт`, на которые не ссылается
  ни одна строка. Чистка идёт после `pull` не чаще раза в час на поток.
  Выключается настройкой.
- `change_stream.purged_seq` — до какого `seq` поток вычищен. `pull` с курсором
  `0 < cursor < purged_seq` отвечает `reset: true` и `reset_reason: "purged"`,
  поток отдаётся с нуля. Существующий сброс (курсор впереди головы) получает
  `reset_reason: "ahead"`.

## Capabilities

### New Capabilities
- `sync-tombstone-retention`: сколько сервер хранит удалённые строки синка,
  как устройства подтверждают прочитанное и что получает устройство, которое
  отстало от чистки.

### Modified Capabilities
- `sync-pull`: сброс курсора впереди головы получает `reset_reason: "ahead"`.
- `ledger-provisioning`: устройство при каждом обращении переписывается на
  текущий леджер пользователя (сейчас остаётся на прежнем — наблюдение Р11
  baseline). Без этого подтверждение леджера после перехода не пишется, а
  телефон ушедшего участника держит горизонт старого леджера.

## Impact

- Миграция: `device.last_ack_reference_seq`, `change_stream.purged_seq`,
  `change_stream.purged_at`; комментарий к `device.last_ack_seq` меняет смысл
  (теперь это подтверждение, а не справка).
- `src/sync.cpp` (`handle_pull`), `src/sync_repo.*` (подтверждение, горизонт,
  чистка, `reset_reason`), `src/provisioning.cpp` (`device.ledger_id`),
  настройки в `main.cpp`.
- `openapi.yaml`: параметр `ledger_id`, поле `reset_reason`; README, раздел про синк.
- Клиенты: android-wallet — отдельный change `purge-synced-tombstones` (сброс с
  нуля с вычисткой локальных строк, параметр `ledger_id`). wallet-telegram —
  без правок. wallet-report/wallet-web уже фильтруют `deleted_at IS NULL`, для
  них удалённые строки просто исчезают.
