# Design

## Context

- `icon` (см. `schema/table/icon.sql`): общая строка — `ledger_id IS NULL`,
  своя — заполненный `ledger_id`; картинка — ссылка `content_sha256` на
  `blob`. Уникальность имени — `uq_icon_name_reference` среди живых общих.
- Общие иконки сейчас создаются только в обход API (`fixture::make_reference_icon`
  в тестах, ручные вставки на проде). Push с телефона пишет общую строку только
  если её `uuid` уже общий (иначе — своя строка леджера).
- `POST /sync/blobs` уже принимает загрузку от браузерной сессии без
  `device_id` (`icon-blobs`), так что загрузку байт веб может переиспользовать.
- Поток справочников — `change_stream` с id
  `00000000-0000-0000-0000-000000000001`; `next_seq(stream)` выдаёт новый
  `seq` (тот же приём, что у `currency_pairs_repo` для леджера).
- Роль пользователя уже разбирается в `session::current_user` (`user.role`,
  по умолчанию `user`), но нигде в wallet-api не проверяется.

## Goals / Non-Goals

**Goals:**
- Минимальная админская запись общего набора, сразу видимая телефонам через pull.
- Не трогать протокол синка и схему БД.

**Non-Goals:**
- Замена картинки у существующей общей иконки (телефон не перекачивает байты
  у уже известной иконки — см. `applyIcon` в android-wallet). Чтобы сменить
  картинку — создать новую иконку.
- Управление своими иконками леджеров с веба.
- Отказ сервера от строк `icon` в `POST /sync/push` (нужен для старых версий
  приложения; можно убрать позже отдельным change).
- Сборка мусора в `blob`.

## Decisions

1. **Двухшаговое создание: байты через `POST /sync/blobs`, затем
   `POST /api/admin/icons` с `content_sha256`.** Альтернатива — multipart или
   base64 в одном запросе. Двухшаговый вариант переиспользует готовую,
   уже проверенную загрузку (лимит 1 МиБ, дедупликация) и тот же порядок
   «сначала байты, потом метаданные», что и у синка. Проверка «blob существует»
   — `SELECT 1 FROM blob WHERE sha256 = $1` в той же транзакции (FK дал бы
   ту же гарантию, но с невнятной ошибкой).
2. **Путь `/api/admin/icons`, а не `/api/reports/admin/icons`.**
   wallet-report работает ролью `wallet_reader` и писать не может; запись —
   только в wallet-api. Гейтвей уже ведёт `/api/*` на wallet-api; префикс
   `/admin/*` (без `/api`) — это google-auth, его не задеваем.
3. **Проверка роли в обработчике**, а не в pre-routing: `access.cpp`
   отвечает за scope, роль — бизнес-правило конкретной ручки (так же, как в
   wallet-report `handle_admin_icons`). Сначала scope (`wallet:write`), потом
   роль — порядок как в сценарии спеки.
4. **Удаление только неиспользуемой иконки (`409` + `in_use`).** Мягкое
   удаление не блокируется внешним ключом; если удалить иконку, на которую
   ссылаются счета, новое устройство получит tombstone иконки и пропустит
   ссылающиеся счета при pull (`applyAccount` ищет иконку локально). Подсчёт
   ссылок — по живым `account`/`currency` во всех леджерах (роль записи
   видит всё).
5. **Каждое изменение — `next_seq(reference)` + `UPDATE/INSERT icon ... seq`**
   в одной транзакции, `updated_by = NULL` (устройства нет). Дубль имени
   ловится по `unique_violation` на `uq_icon_name_reference` → `409`.
6. **Валидация имени: trim, 1–64 символа.** Существующие имена — до 24
   символов; 64 — запас без риска для UI телефона.

## Risks / Trade-offs

- [Админ создаёт общую иконку с именем, совпадающим со своей иконкой
  пользователя на телефоне] → у сервера индексы раздельные, конфликт решает
  телефон (см. android change, переименование локальной иконки).
- [Загруженный в `/sync/blobs` файл — не картинка] → сервер формат не
  проверяет (как и сейчас для телефона); веб конвертирует в WEBP 256×256
  перед загрузкой. Защита — лимит 1 МиБ и admin-only создание строки.
- [Осиротевшие blob, если админ загрузил байты, но не создал иконку] →
  принимаем; сборка мусора по blob — отдельная задача.

## Migration Plan

Миграции схемы нет. Выкатка wallet-api до wallet-web: веб без ручек просто
получит `404` на «Добавить». Откат — откат образа; созданные общие иконки
остаются валидными строками синка.
