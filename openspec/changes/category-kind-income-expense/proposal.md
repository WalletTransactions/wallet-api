# Proposal

## Why

У категории нет понятия «доход» или «расход»: направление определяется только
проводкой («кошелёк → категория» — расход, «категория → кошелёк» — доход). Поэтому
в окне операции «Зарплата» предлагается в «Статье расхода», а «Продукты» — в
«Статье дохода». Пикер не может отфильтровать список, потому что фильтровать не по
чему: признака нет ни на клиенте, ни в схеме. Нужен явный признак на самой
категории, который ходит через синк, как `system_kind` и `kind`.

## What Changes

- Новая колонка `account.category_kind smallint NOT NULL DEFAULT 2`, значения
  `0` = расход, `1` = доход, `2` = оба. Для кошельков и системных категорий
  (`system_kind <> 0`) всегда `2`.
- Миграция `000041`: добавляет колонку и размечает существующие категории по
  живым проводкам: только «категория → кошелёк» → `1`, только «кошелёк →
  категория» → `0`, обе стороны или ни одной → `2`; системные категории → `2`.
  Изменённым строкам выдаётся новый `seq` (`next_seq` на каждый леджер), чтобы
  разметка дошла до устройств через `/sync/pull`.
- `/sync/push` и `/sync/pull`: строка `account` несёт `category_kind`. Колонка
  обязательная: строка без неё — `400 invalid_row`, значение вне `0..2` — тоже
  `400`. Обратной совместимости со старыми клиентами не требуется.
- Справочный DDL `schema/table/account.sql`, `openapi.yaml` (`AccountPushRow`,
  `AccountPullRow`), `README.md` — описание нового поля.
- **BREAKING**: клиент без `category_kind` в строке `account` получает `400`.
  Android правится отдельным change в `android-wallet`; `wallet-telegram`
  строки `account` не пишет, правка ему не нужна.

## Capabilities

### New Capabilities
- `category-kind`: вид категории (расход / доход / оба) — хранение, допустимые
  значения, правило для кошельков и системных категорий, разметка существующих
  категорий по истории проводок.

### Modified Capabilities
- `sync-push`: строка `account` несёт обязательную колонку `category_kind`
  со значениями `0..2`.

## Impact

- `wallet-api`: миграция `000041_category_kind.up/down.sql`, `schema/table/account.sql`,
  `src/sync_repo.cpp` (`push_tables()`), `openapi.yaml`, `README.md`, тесты
  `tests/test_sync_repo.cpp` и `tests_integration/`.
- `android-wallet`: пикер «Статья расхода» / «Статья дохода», создание и карточка
  категории, справочник — отдельный change (зависит от этого).
- `wallet-report`, `wallet-web`, `wallet-telegram`: не затрагиваются сейчас;
  фильтр категорий по виду в отчётах и в резолвере бота — отдельно позже.
- Новое поле читается ролью `wallet_reader` без правки прав: `account` уже
  доступен ей на чтение.
