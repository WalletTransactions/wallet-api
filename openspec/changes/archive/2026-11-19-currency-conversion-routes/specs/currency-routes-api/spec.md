# Spec Delta

## Purpose

Веб-управление маршрутами пересчёта валют цепочкой шагов (тег
`currency-routes` в `openapi.yaml`): просмотр, создание по пути из валют и
удаление маршрутов леджера; изменения доходят до телефонов обычным синком.

## ADDED Requirements

### Requirement: Маршруты только своего леджера
Маршрут SHALL принадлежать одному леджеру; общих маршрутов нет. Ручки SHALL
видеть только маршруты леджера вызывающего, чужие неотличимы от
несуществующих (`404`).

#### Scenario: Чужой маршрут
- **WHEN** пользователь удаляет маршрут чужого леджера
- **THEN** ответ `404`, маршрут не изменён

### Requirement: Список маршрутов
`GET /api/currency-routes` (`listCurrencyRoutes`) SHALL возвращать живые
валидные маршруты леджера: `from`, `to` (uuid, ISO-код), путь из валют и шаги
(пара и направление) в порядке `num`. Пользователь без леджера получает пустой
список, а не `404`, леджер не создаётся. Недостроенная цепочка в список не
попадает.

#### Scenario: Новый пользователь
- **WHEN** пользователь без леджера открывает список маршрутов
- **THEN** ответ `200`, `routes` пуст, леджер не создан

#### Scenario: Маршрут из двух шагов
- **WHEN** у леджера маршрут `BTC → EUR → RUB`
- **THEN** в списке один маршрут `from` = BTC, `to` = RUB, путь `BTC, EUR, RUB`, два шага

### Requirement: Создание маршрута по пути из валют
`POST /api/currency-routes` с `currency_uuids` (3–4 попарно различные валюты,
видимые леджеру) SHALL подобрать для каждой соседней пары валют видимую живую
валютную пару, записать шаги маршрута одной группой и ответить `201`. Леджер
при необходимости создаётся.

#### Scenario: Успех
- **WHEN** есть пары `BTCEUR` и `EURRUB`, пользователь шлёт путь `BTC, EUR, RUB`
- **THEN** ответ `201`, созданы два шага, `from` = BTC, `to` = RUB

#### Scenario: Шаг по обратной паре
- **WHEN** для шага `EUR→RUB` есть только пара `RUBEUR`
- **THEN** ответ `201`, шаг записан с обратным направлением

#### Scenario: Нет пары для шага
- **WHEN** для соседних валют `EUR`, `RUB` пары нет
- **THEN** ответ `400` с названием шага, ничего не создано

#### Scenario: Повторяющиеся или слишком много валют
- **WHEN** путь содержит валюту дважды, или короче трёх, или длиннее четырёх валют
- **THEN** ответ `400`

#### Scenario: Невидимая валюта
- **WHEN** валюта пути принадлежит чужому леджеру
- **THEN** ответ `400` «валюта не найдена», как для несуществующей

#### Scenario: Дубль маршрута
- **WHEN** у леджера уже есть живой маршрут между теми же `from` и `to`, в том числе в обратном порядке
- **THEN** ответ `409`, ничего не создано

### Requirement: Удаление маршрута
`DELETE /api/currency-routes/{from}/{to}` SHALL мягко удалять все шаги своего
маршрута одной группой (`204`). Курсы и пары шагов не меняются. Чужой или
несуществующий маршрут — `404`.

#### Scenario: Удаление и повторное создание
- **WHEN** маршрут удалён, и затем создаётся снова с тем же путём
- **THEN** ответ `201`, дубля нет

### Requirement: Изменения едут в синк
Каждое создание и удаление SHALL быть одной транзакцией с одним новым `seq`
потока леджера и приходить на устройства обычным `GET /sync/pull` строками
`currency_conversion`. `updated_by` пуст. Роль участника не проверяется — как у
`currency-pairs-api`.

#### Scenario: Маршрут с веба на телефоне
- **WHEN** пользователь создал маршрут из двух шагов в вебе
- **THEN** при следующем pull телефон получает обе строки в `ledger.changes.currency_conversion` с одним `seq`
