# Proposal

## Why

Клиенты (android-wallet, wallet-web) получают возможность задавать маршруты
пересчёта валют цепочкой шагов (например, `BTC → EUR → RUB`), чтобы эквивалент
считался и там, где прямой пары нет. wallet-api владеет схемой Postgres,
вьюхами курса и контрактом синка, поэтому без его изменения маршруты нельзя ни
сохранить, ни учесть в серверных расчётах (`balance_series`, `capital_assets`,
отчёты). Сегодня таблица `currency_conversion` в синке есть, но вьюха
`v_currency_conversion` строится от существующих пар и лишь подменяет у их
направлений `currency_pair_uuid`; маршрут из нескольких шагов она выразить не
может.

## What Changes

- Таблица `currency_conversion` сохраняет колонки `from_currency_uuid`,
  `to_currency_uuid`, `num`, `currency_pair_uuid`, `is_reverse`, но меняет
  смысл: **маршрут** `from → to` — это цепочка строк, где `num` — номер шага
  (1…3), а каждая строка называет пару и направление шага. Маршрут
  принадлежит леджеру (`ledger_id NOT NULL`, общих маршрутов нет). Один живой
  маршрут на неупорядоченную пару `from`/`to`. Альтернативных маршрутов между
  одной парой валют нет.
- Маршрут двунаправленный: `BTC → EUR → RUB` даёт и курс RUB→BTC.
- `/sync/push` и `/sync/pull` несут строки шагов в этой форме
  (`CurrencyConversionPushRow` / `PullRow` в `openapi.yaml`). Целостность цепочки
  (непрерывные `num`, шаги стыкуются, концы совпадают с `from`/`to`) в push не
  проверяется — шаги могут приходить разными батчами; недостроенная цепочка
  просто не даёт курса. Построчная валидация: `num` 1…3, `from` ≠ `to`,
  пара существует. **BREAKING** для контракта синка в части ограничений на
  строку (раньше `num` ≥ 0, ограничений на содержимое не было); совместимость
  со старыми клиентами не сохраняется.
- Новый REST для кабинета (wallet-web ходит в `/api/currency-pairs*`, а не в
  синк): список, создание и удаление маршрутов (`/api/currency-routes*`). Клиент
  присылает **путь из валют** (`BTC, EUR, RUB`), сервер сам подбирает пары и
  направления и записывает шаги одной транзакцией; изменения едут в синк.
- Удаление пары через REST мягко удаляет и маршруты, использующие её, одной
  группой с курсами пары — как уже удаляются её курсы.
- Вьюха `v_currency_conversion_rate` дополняется составными строками
  `(from, to, date, rate)`: произведение курсов шагов, каждый шаг — последний
  курс не позже даты независимо; строки выдаются на даты изменения любого из
  шагов. **Если у `(from, to)` есть хотя бы один живой прямой курс (в любую
  сторону), маршрут для этой пары не применяется вовсе.** **По умолчанию
  кросс-курсы считаются через USD**: для пары без прямого курса и без явного
  маршрута курс = `A→USD` × `USD→B` по прямым курсам (приоритет: прямой →
  явный маршрут → USD). Потребители вьюхи
  (`balance_series`, `capital_assets`, отчёты) контрактом не меняются.
- Миграция схемы и пересоздание зависимых вьюх; проверка стоимости запроса
  курса в `balance_series` (резолв курса вызывается на пару дата × валюта).

## Capabilities

### New Capabilities
- `currency-routes-api`: REST `/api/currency-routes*` — список, создание
  (по пути из валют), удаление маршрутов леджера; изменения едут в синк.
- `currency-route-rates`: правила составного курса, которые видят серверные
  расчёты и отчёты: цепочка шагов, двунаправленность, независимые даты шагов,
  приоритет прямой пары, обрыв и недостроенная цепочка.

### Modified Capabilities
- `sync-push`: построчная валидация шага маршрута (`currency_conversion`).
- `currency-pairs-api`: удаление пары снимает использующие её маршруты.

## Impact

- Код/схема: новая миграция в `migrations/` (ограничения таблицы, индексы,
  вьюхи, агрегат произведения), `sync_repo.cpp` (область `LedgerOnly`, ссылки,
  проверки), новый `currency_routes*.cpp/.hpp`, `currency_pairs_repo` (каскад
  на маршруты), `openapi.yaml`.
- Потребители вьюхи в БД: `balance_series` (миграции 000017–000019),
  `capital_assets` (000033), отчёты wallet-report и MCP — через курс; запросы не
  меняются, но нужна регрессия по расчётам и план запроса.
- Смежные change с тем же именем: android-wallet, wallet-web, wallet-report.
- Риск: рост стоимости резолва курса из-за составных строк; оценить планом
  запроса на данных, близких к проду (см. design).
