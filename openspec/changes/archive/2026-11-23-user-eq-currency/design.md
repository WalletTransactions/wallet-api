## Context

- Пользователь — `app_user` (wallet-api). Леджеров у него может быть несколько
  (`ledger_member` PK `(ledger_id, user_id)`), запрос работает с леджером
  сессии.
- Валюты (`currency`) — по леджерам, плюс общий справочник (`ledger_id IS
  NULL`); uuid валюты у разных леджеров разный, ISO-код — общий.
- Scope сессии веба и Android: `wallet:read wallet:write reports:read account
  ai:use docs:ask`; бот и MCP — `reports:read`.

## Decisions

### D1. Хранить ISO-код, а не uuid валюты

uuid валюты свой у каждого леджера, а предпочтение — у пользователя. ISO-код
переносится между леджерами и совпадает с тем, что уже хранят веб и Android.
Если в текущем леджере такой валюты нет, клиенты берут запасную (EUR, затем
первую) — правило у них, а не здесь.

### D2. Личная таблица, а не колонка `app_user`

`user_settings(user_id PK → app_user ON DELETE CASCADE, eq_currency_iso text
NULL, updated_at)`. Отдельная таблица — место для будущих личных настроек
(кошелёк по умолчанию, формат даты) без правок `app_user`. Нет строки и
`NULL` означают одно и то же — «не выбрано».

### D3. Проверка кода при записи

`PUT` принимает код, только если он есть среди живых валют, видимых леджеру
пользователя (те же правила, что у `/api/reports/currencies`); регистр
приводится к верхнему. Иначе `400 {"error":"unknown_currency"}`. `null` —
сброс. Без леджера — только общий справочник.

### D4. Scope `account`

Настройка личная, не данные леджера: участник с ролью reader тоже может её
менять. `account` есть только у полноценной сессии, поэтому токены бота и MCP
не могут ни читать, ни менять её через wallet-api.

## Risks / Trade-offs

- [Код валюты удалили из справочника после выбора] → Значение остаётся,
  клиенты видят, что валюты нет, и берут запасную.
