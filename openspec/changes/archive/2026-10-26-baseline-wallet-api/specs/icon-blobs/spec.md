# Spec Delta

## Purpose

Хранение и выдача двоичного содержимого иконок отдельно от протокола
push/pull: байты загружаются один раз по адресу SHA-256, а строка `icon` в
синке ссылается на них хешем.

## ADDED Requirements

### Requirement: Загрузка содержимого
`POST /sync/blobs` (`uploadBlob`) SHALL принимать тело запроса как есть, от
1 байта до 1 МиБ, без разбора `Content-Type`, сам вычислять SHA-256 и
отвечать `200` `{"sha256":"<64 hex>"}`. Тело вне этих границ — `400`.

#### Scenario: Загрузка иконки
- **WHEN** клиент загружает PNG размером 4 КиБ
- **THEN** ответ `200` с SHA-256 этих байт, посчитанным сервером

#### Scenario: Пустое тело
- **WHEN** тело запроса пустое
- **THEN** ответ `400`

### Requirement: Идемпотентность и дедупликация
Одинаковое содержимое SHALL храниться один раз для всех пользователей.
Повторная загрузка тех же байт ничего не меняет и возвращает тот же хеш.

#### Scenario: Двое загрузили одну картинку
- **WHEN** два разных пользователя загружают одинаковые байты
- **THEN** оба получают один и тот же `sha256`, в хранилище одна запись

### Requirement: Выдача содержимого
`GET /sync/blobs/{sha256}` (`downloadBlob`) SHALL отдавать сохранённые байты
как `application/octet-stream`. Параметр не из 64 hex-символов — `400`,
неизвестный хеш — `404`.

#### Scenario: Содержимого нет
- **WHEN** запрошен корректный, но не загруженный хеш
- **THEN** ответ `404`

### Requirement: Доступ без устройства и без привязки к леджеру
Обе ручки SHALL требовать только аутентификацию и scope (`wallet:write` на
загрузку, `wallet:read` на выдачу), без claim'а `device_id`. Право прочитать
конкретный blob по видимости иконки в леджере вызывающего не проверяется.

#### Scenario: Браузерная сессия читает иконку
- **WHEN** токен без `device_id` со scope `wallet:read` запрашивает существующий blob
- **THEN** ответ `200` с байтами

### Requirement: Порядок загрузки и синка
Строка `icon` в `POST /sync/push` SHALL ссылаться на уже загруженное
содержимое. Ссылка на незагруженный хеш даёт `409 missing_reference`
(см. `sync-push`).

#### Scenario: Сначала метаданные, потом байты
- **WHEN** клиент присылает строку `icon` до загрузки её содержимого
- **THEN** push отклонён `409`; после `POST /sync/blobs` тот же батч проходит
