## Context

`000037_default_reference_icons` генерируется `scripts/gen_default_icons.py` из `migrations/default_icons/manifest.json` и PNG. Накатанную миграцию нельзя переписывать (golang-migrate хранит только номер версии, второй раз её не запустит), а набор телефона растёт — значит, прирост должен ехать новой миграцией, собранной тем же генератором.

## Goals / Non-Goals

**Goals:**
- Две иконки (`Flag BTC`, `Flag LTC`) есть в базе по умолчанию.
- Один генератор и один манифест на все миграции набора; `000037` байт-в-байт прежняя.

**Non-Goals:**
- Не наполняем справочник общих валют и пар (`currency`/`currency_pair` с `is_shared`) — это отдельная работа администратора.
- Не меняем API и протокол синка.
- Иконки кошельков «Наличные» и «Кредитная карта» не добавляем: используются уже существующие `USD banknote` и `Visa card`.

## Decisions

1. **`since` в записи манифеста.** Запись без поля — миграция 37; новые получают номер своей миграции. Альтернатива — второй манифест на миграцию — дублировала бы проверки уникальности имён; одно поле проще и позволяет тесту проверить «имя добавлено ровно одной миграцией».

2. **`collect` добавляющий.** Он не пересоздаёт PNG уже известных имён: байты картинок вшиты в накатанную `000037`, и другая версия `cairosvg` или другой флаг изменили бы то, что генератор пишет в `000037`, — а тест `test_committed_sql_is_what_the_generator_writes` тогда упал бы. Если телефон *изменит* картинку существующей иконки, это уже не добавление, а замена: отдельное решение и отдельная миграция.

3. **Таблица `MIGRATIONS` в генераторе** (номер → суффикс имени файла). Новая миграция — строка в таблице и `collect --since N`; тест проверяет, что у каждой миграции таблицы есть иконки, и наоборот.

4. **Идемпотентность и уважение администратора — как у 000037.** Тот же SQL-шаблон: детерминированный `uuid`, `ON CONFLICT DO NOTHING`, пропуск имени, занятого живой общей иконкой.

## Risks / Trade-offs

- [Манифест перестаёт быть простым списком «имя → файл»] → поле `since` необязательное, у 87 прежних записей его нет, формат читается как раньше.
- [Растеризация векторных флагов зависит от версии `cairosvg`] → PNG лежат в репозитории; `build` их только читает, `collect` затрагивает только новые имена.

## Migration Plan

Накат `000038` через обычный deploy `wallet-api` (golang-migrate). Откат `000038.down.sql` убирает только `Flag BTC` и `Flag LTC` и осиротевшие `blob`. Клиенты ничего не ждут: иконки приходят через `reference`-поток.
