# Proposal

## Why

Набор иконок по умолчанию (`000037_default_reference_icons`) — снимок стартового набора телефона на 2026-11-13. С тех пор набор телефона вырос: в `new-user-default-set` (android-wallet#29) добавлены валюты BTC и LTC с флагами `Flag BTC` и `Flag LTC`, а телефон пушит на сервер каждую встроенную иконку, которой там нет. Пока этих двух иконок в базе по умолчанию нет, новый пользователь при первом синке заливает их сам, чистая база (после `test-refresh`) остаётся без них, а веб не показывает флаги BTC и LTC в форме валют.

Следующий шаг — два кошелька «Наличные / Cash» и «Кредитная карта / Credit card» в стартовом наборе телефона. Их иконки (`USD banknote`, `Visa card`) уже есть в `000037`, поэтому для них миграция не нужна — но это правило («иконки набора телефона есть на сервере по умолчанию») нужно закрепить: любое расширение набора телефона едет новой миграцией этого же генератора.

## What Changes

- Новая миграция `000038_default_reference_icons_btc_ltc`: общие иконки-флаги `Flag BTC` и `Flag LTC` (`icon_type` = 1), те же имена и картинки, что в `seed.json` телефона.
- Генератор `scripts/gen_default_icons.py` умеет несколько миграций набора: у записи манифеста есть поле `since` (номер миграции, по умолчанию 37), `build` пишет по паре файлов на каждый `since`, `collect` только добавляет новые имена и не пересоздаёт уже собранные PNG (их байты вшиты в накатанную `000037`).
- `000037` не переписывается: файлы остаются байт-в-байт прежними.
- Тесты: генератор (миграции из манифеста, набор `000037` не меняется, 38 добавляет ровно BTC и LTC) и интеграционные (`test_default_icons.cpp`: накат/откат/повтор `000038`, иконка администратора с тем же именем не затирается).
- API, контракты `/sync/*` и клиенты не меняются. **BREAKING** нет: набор только дополняется.
