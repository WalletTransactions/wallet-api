# Design

## Context

- `POST /sync/blobs` (`blob.cpp::handle_upload`): аутентификация, размер 1 Б –
  1 МиБ, `INSERT … ON CONFLICT DO NOTHING`. Им пользуются и телефон (раньше), и
  админ веба (`createReferenceIcon`), поэтому запретить загрузку целиком нельзя.
  `session::User` несёт `role`.
- `POST /sync/push` (`sync_repo.cpp`): таблица `icon` — `Scope::ReferenceOrLedger`,
  порядок применения `icon` первой. Ответ при успехе — `{seq, conflicts: []}`,
  он же пишется в `sync_push_batch` для идемпотентного повтора.
- `GET /sync/pull` (`sync.cpp`): `{ledger, reference}`, поля верхнего уровня
  больше нет. Конфиг читается из env в `main.cpp`, раскладывается в `AppState`
  (пример — `SYNC_TOMBSTONE_PURGE`).
- Клиент `android-wallet` после `server-managed-icons` иконок не шлёт; парный
  change вернёт отправку как опцию.

## Goals / Non-Goals

**Goals:**
- Оператор выключает приём своих иконок одной переменной, синк остального живёт.
- Клиент узнаёт о запрете заранее (pull) и по однозначному коду отказа.

**Non-Goals:**
- Флаг на пользователя/леджер и экран админа для него (флаг глобальный).
- Квоты и лимит числа иконок (решено: пока без лимита; лимит blob 1 МиБ остаётся).
- Удаление уже загруженных своих иконок при выключении флага.

## Decisions

1. **Флаг — `LEDGER_ICON_UPLOAD`, `AppState::ledger_icon_upload`.** Разбор как у
   `SYNC_TOMBSTONE_PURGE`: `on/true/1` включает, остальное — выкл. По умолчанию
   **выкл**: выкатка нового wallet-api не открывает приём сама. Читается один
   раз при старте, строка в лог (`event: ledger_icon_upload_config`).
2. **Blob: 403 только не-админу.** Проверка в `handle_upload` после
   `current_user` и до проверки размера: `!state.ledger_icon_upload &&
   user->role != "admin"` → `403 {"error":"icon_upload_disabled"}`. Альтернатива —
   выключить ручку для всех: ломает админский `createReferenceIcon`.
3. **Push: фильтр, а не отказ.** До применения батча из `changes` убираются
   строки `icon`, если флаг выключен. Ответ получает
   `icons_rejected: {error, uuids[]}`; без отброшенных строк поля нет — ответ
   остальных клиентов не меняется. Альтернатива «403 на весь батч» отвергнута:
   клиенту пришлось бы повторять push без иконок, а выключенный флаг блокировал бы
   синк денег. Фильтр действует и для `PushMode::CreateOperationsOnly` (бот иконок
   не шлёт — различия нет).
   Строки счёта/валюты со ссылкой на отброшенную иконку дают штатный
   `409 missing_reference` (заместитель — забота клиента, он подставляет
   серверную иконку до отправки; см. design клиента).
4. **Идемпотентность.** `icons_rejected` входит в `response_text`, который
   пишется в `sync_push_batch`, поэтому повтор того же `batch_id` вернёт тот же
   ответ. Флаг на момент повтора не пересматривается — как и остальная часть
   ответа.
5. **Pull: `capabilities.icon_upload`** на верхнем уровне ответа рядом с
   `ledger`/`reference`. Блок обязательный в каждом ответе, значение — флаг.
   Новое поле безопасно для старых клиентов (JSON-парсеры игнорируют неизвестное).
   Расширяемо под будущие флаги.
6. **Один код `icon_upload_disabled`** для 403 blob и для `icons_rejected` —
   клиент различает его от `missing_reference`/`invalid_row`.

**Правки в других сервисах:**
- android-wallet — парный change (настройка, отправка, реакция на код).
- wallet-infra — `LEDGER_ICON_UPLOAD` в `test.env`/`prod.env` (по умолчанию
  оставить off; включение — отдельным PR + rc-тег).
- wallet-telegram, wallet-report, wallet-web — без правок.
- Миграций БД нет.

## Risks / Trade-offs

- [Клиент отправил иконку и счёт одним батчем, флаг выключен] → иконка
  отброшена, счёт ловит `409 missing_reference`. Клиент по `icons_rejected` из
  предыдущего ответа или по `capabilities` из pull не должен до этого доходить;
  если дошёл — выключает переключатель и повторяет с заместителем.
  `409` приходит раньше, чем клиент увидит `icons_rejected` (батч откатывается
  целиком, `icons_rejected` в ответе `409` нет). Поэтому клиенту нужен pull
  с `capabilities` как основной источник знания о флаге, а `403` на blob — как
  второй сигнал.
- [Флаг меняется между pull и push] → гонка допустима: худший исход — один
  `403` на blob, после которого клиент выключает отправку.
- [Админ с ролью `admin` через телефон грузит иконки при выключенном флаге] →
  разрешено намеренно, это тот же канал, что у веба.
- [Выключение флага не чистит уже загруженные свои иконки] → осознанно (non-goal).

## Migration Plan

1. Релиз wallet-api с флагом off по умолчанию (поведение не меняется для
   всех клиентов, кроме нового поля pull).
2. PR в wallet-infra: `LEDGER_ICON_UPLOAD=on` для test, проверка с Android.
3. Позже — prod. Откат — вернуть `off` и перезапустить сервис.
